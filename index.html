01 / Introduction

Where software meets electronics.

The Java application runs the game on a computer. The Arduino controller reads the buttons. Serial communication connects these two parts, allowing physical input to control software.

01

The controller board

An Arduino board contains a microcontroller: a small programmable chip with digital input and output pins. It runs the uploaded sketch and checks button states. It is a controller board, not a PC motherboard.

02

The push buttons

Buttons are switches—not microcontrollers themselves. Pressing a button changes the electrical state of a pin. The sketch translates that change into a direction command.

03

The Java game

Java receives a command, validates it, and requests a new direction. The game loop remains responsible for movement, food, score, collisions, and drawing the board.

Up D2 U\n Request upward movement

Here, \n means a newline byte, not the literal characters backslash and n. Arduino Serial.println normally sends CRLF; Java’s line reader can handle that too.

Physical Arduino connection

Buttons → Arduino → USB serial → Java

A USB-connected board usually exposes a serial device, sometimes through a USB-to-serial chip. Java opens that device’s port. com0com is not needed for this route.

Virtual-port connection test

PuTTY → COM5 ⇄ COM6 → Java

com0com creates two connected virtual ports on Windows. Data written into one end appears at the other. PuTTY sends test commands instead of an Arduino.

Wokwi needs a separate connection plan. Wokwi can simulate the circuit and show sketch output in its Serial Monitor. That browser simulation does not automatically become a Windows COM port. To reach desktop Java, use a serial-forwarding integration supported by your Wokwi environment, or move to a physical Arduino. com0com alone is not that bridge.
03 / Code explained

Different languages. One shared protocol.

The Arduino .ino sketch is compiled as C/C++ and runs on the microcontroller, or a simulated microcontroller in Wokwi. The Java application runs inside the JVM on your computer. They exchange bytes—not direct function calls.

Arduino: read, debounce, send

This illustrative sketch uses D2–D5 and INPUT_PULLUP. Wire each button between its input pin and GND: released is HIGH, pressed is LOW. It sends one command per stable press and does not repeat continuously while held. 

// Illustrative sketch. Match these values to your real project.
const byte pins[] = {2, 3, 4, 5};
const char commands[] = {'U', 'D', 'L', 'R'};

bool lastReading[] = {HIGH, HIGH, HIGH, HIGH};
bool stableState[] = {HIGH, HIGH, HIGH, HIGH};
unsigned long changedAt[] = {0, 0, 0, 0};

const unsigned long debounceMs = 30;

void setup() {
  Serial.begin(9600);

  for (byte i = 0; i < 4; i++) {
    pinMode(pins[i], INPUT_PULLUP);
  }
}

void loop() {
  unsigned long now = millis();

  for (byte i = 0; i < 4; i++) {
    bool reading = digitalRead(pins[i]);

    if (reading != lastReading[i]) {
      changedAt[i] = now;
      lastReading[i] = reading;
    }

    if (now - changedAt[i] >= debounceMs
        && reading != stableState[i]) {
      stableState[i] = reading;

      if (stableState[i] == LOW) {
        Serial.println(commands[i]);
      }
    }
  }
}

Debouncing filters the rapid contact changes that can happen during a physical press. In Wokwi, run the simulation and check that each button produces the expected command in the Serial Monitor.

Java: receive, validate, queue

The following is an integration example using jSerialComm, not a claim about the library used in this repository. It belongs inside your application’s serial-input component. The game loop should consume the queued commands safely. 

// Add jSerialComm to your build before using this example.
import com.fazecast.jSerialComm.SerialPort;
import java.io.BufferedReader;
import java.io.InputStreamReader;
import java.nio.charset.StandardCharsets;
import java.util.concurrent.ArrayBlockingQueue;
import java.util.concurrent.BlockingQueue;

// Members of your serial-input component:
private final BlockingQueue<String> inputs =
    new ArrayBlockingQueue<>(32);

public void readController(String portName) {
    SerialPort port = SerialPort.getCommPort(portName);
    port.setComPortParameters(
        9600, 8, SerialPort.ONE_STOP_BIT, SerialPort.NO_PARITY
    );
    port.setFlowControl(SerialPort.FLOW_CONTROL_DISABLED);
    port.setComPortTimeouts(
        SerialPort.TIMEOUT_READ_BLOCKING, 0, 0
    );

    if (!port.openPort()) {
        System.err.println("Cannot open " + portName);
        return;
    }

    try (BufferedReader reader = new BufferedReader(
            new InputStreamReader(
                port.getInputStream(), StandardCharsets.US_ASCII))) {

        String line;
        while ((line = reader.readLine()) != null) {
            String command = line.trim();

            if (command.matches("[UDLR]")) {
                inputs.offer(command);
            }
        }
    } catch (Exception error) {
        System.err.println("Serial error: " + error.getMessage());
    } finally {
        port.closePort();
    }
}

Run the blocking reader on a background thread, not the UI thread. During each game tick, consume at most one eligible direction request and reject movement directly opposite to the snake’s current direction. Add connection shutdown and reconnection handling in the complete application.

Does Java send anything back? Not necessarily. This guide describes one-way controller input. A two-way protocol could later send scores, status, or LED commands back to the board, but both programs would need to implement those messages.
04 / Getting started

Build the connection step by step.

Software

  • Git and a compatible Java JDK.
  • An IDE or the repository’s build tool.
  • The serial library required by the Java project.
  • Wokwi for circuit and sketch simulation.
  • PuTTY and com0com for Windows virtual-port tests.
  • Arduino IDE or another uploader for real hardware.

Optional physical hardware

  • A compatible Arduino board.
  • Four push buttons.
  • A breadboard and jumper wires.
  • A USB data cable.
  • No external pull-up resistors for this INPUT_PULLUP example.

Wire with the board powered off. Check the board pinout and the connected legs of four-terminal push buttons.

  1. Clone and inspect the project

    git clone https://github.com/Jasurlv/snake-game.git
cd snake-game

    Open the project in your IDE. Check its build files for the required JDK and dependencies. Locate the game entry point and serial configuration. The exact build and run commands depend on the repository.

  2. Check the Wokwi controller

    Wokwi project link

    Open the project’s Wokwi by link top, or create a matching circuit. Wokwi commonly uses sketch.ino and diagram.json. If your sketch is called scatch.ino, use or rename it as required by your environment. Start the simulation, press each button, and inspect Serial Monitor output.

  3. Create a virtual serial pair

    download com0com here

    For a Windows-only software test, install a trusted, compatible com0com driver and create a free port pair. This guide uses COM5 and COM6 as examples. Use the actual names shown on your machine; do not overwrite existing ports.

  4. Connect Java to one end

    Configure the Java application to open COM6 at 9600 baud, 8N1, with flow control disabled. Launch the game using its real entry point. Confirm that opening the port succeeds.

  5. Connect PuTTY to the other end

    download PuTTY here

    In PuTTY, select Serial, enter COM5, and use matching settings. Send U, D, L, or R followed by a line ending. In a typical PuTTY configuration, Enter sends carriage return, which the illustrated Java readLine parser accepts. If your actual parser requires LF, send LF explicitly, commonly with Ctrl+J.

  6. Test the actual controller route separately

    For real hardware, upload the sketch, close other serial monitors, and point Java at the Arduino’s USB serial port. For Wokwi-to-Java control, first configure and document a supported bridge. Neither route is proven solely by a successful PuTTY/com0com test.

07 / Troubleshooting

When something does not connect.

Java cannot open the port

Check that the port exists and the name matches exactly. Close applications using that same endpoint. In the paired-port test, PuTTY and Java must open opposite ends. Verify driver installation and operating-system permissions.

Commands appear in Wokwi, but not in Java

Wokwi Serial Monitor output is not automatically delivered to a desktop COM port. Confirm that a supported bridge is installed, configured, and forwarding to the endpoint Java opens. Otherwise, use PuTTY for the virtual-port test or real hardware.

The port opens, but the snake does not move

Log incoming commands before changing game state. Check the command spelling, line ending, port pairing, and game state. Verify that the game loop consumes the input and that the requested turn is not correctly rejected as an illegal reversal.

One press produces multiple commands

Add debouncing and send only on the released-to-pressed transition. Continuously sending while a button is held can fill the input queue and cause delayed turns.

The game window freezes while waiting for input

Move blocking serial reads off the UI thread. Transfer input through a thread-safe queue, and keep UI updates on the thread required by your framework.
